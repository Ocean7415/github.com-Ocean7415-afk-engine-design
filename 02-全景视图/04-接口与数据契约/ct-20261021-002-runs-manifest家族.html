§0 一句话

解决什么：定义夜车排期单（runs/manifest-*.json）的家族契约——顶层声明版本清单与闸参数，versions[] 每元素=一波。为什么存在：manifest 是业主资产（改它=改排期意图），家族字段差异（v2 无 project_ref/w16 无 _comment 等）必须逐键落约，runner 消费语义才不会读错旧排期单（W-041 三家族逐键比对·90-过程/执行台账.md:583）。边界：本卡只投影契约——出题权/排期权不在施工窗，代理只读不写 manifest。

节点详注表（图正下方·每节点做什么/边界/锚点）：

节点详注
manifest 排期单夜车的排期输入与业主资产：versions/闸参数改动=改排期意图须拍板依据——代理施工只读不写（出题权/排期权红线）。
validateDecisionRef入队资格闸：每版 decision_ref（如「拍板#27」）逐版校验——任一拒=整个 manifest 不派（锚 ts/src/queue/queue-runner.ts:7·fail-closed 拒面在派工前）。
逐版串行消费主循环（锚 ts/src/queue/queue-runner.ts:2）：按 versions[] 顺序叫号，不并行不跳版——排期纪律机械化。
inherits 继承跨班工作区继承（拍板#65·锚 ts/src/queue/queue-runner.ts:42）：指向同 manifest 内先行班 id，派工首轮前搬入其终态工作区——迭代版站在前版肩膀上。
派班施工波次执行：每版走站3→站4→站5 三站流水+班内判卷（时序见 sq-20261021-001）——本卡只管「哪版先哪版后」。
闸参数落账max_final_reds 随 gate 事件 payload.threshold 落账（对表见 ct-20261021-001）；max_rounds 限定每版维修轮帽——防烧钱双闸。
排期唯一守卫旧根已有排期=新窗 id 续 -r2/-r3（锚 pipeline-lab/scripts/fail-loop.mjs:93）——同一根名不重排，历史排期不被覆盖。
