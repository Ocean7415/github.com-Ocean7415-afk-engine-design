# 模块卡 · 岗位持续化会话（十六岗位评估定稿 · run13-16 四轮实证驱动）

## §0 一句话

**解决什么**：run13-16 四轮四形态未收敛（781,001 tokens 零交付）的根因=站 4 车道是「无状态单轮重写」（底座 `llm.ts:85` messages 仅一条 user·每轮从零选架构·回喂盒空喂盲改）——本卡给**有迭代闭环的岗位装「票级持久会话」**（写→测→红→**同会话追加回喂**→精修），把 L2 会话式迭代的结构优势移植进 L1 车道（L2 实锚：cacheRead 7,686,848+332k 全绿）。**为什么现在**：#498/#499/#500 三只红因提示盒已装但「明细给了无药方盲改」升级为「药方给了仍重抽」——提示模板对一次到位率 gap 杠杆有限（四轮实证）·迭代结构才是根因。

## §三条判定法则（持续化资格标尺）

| 法则 | 内容 | 判定 |
|---|---|---|
| ① 迭代闭环法则 | 有「写→测→红→改」多轮闭环的岗位→持续化（精修代重抽+缓存命中双收） | ✓ 持续化 |
| ② 独立性法则 | 裁决/审查/诊断类岗位→不持续化（新鲜眼防锚定偏差·分权设计：看病的/开方子的/动刀的） | ✗ 保持单发 |
| ③ 单发起草法则 | 一次性起草（草稿/建议/注记·无迭代闭环）→不持续化 | ✗ 保持单发 |

**红线**：判卷闸族（judge-guard/symbol-gate/probe-gate/mutation-gate/crap-gate/ladder）**严禁持续化**——LLM 进判卷=考生自判（判卷语义零触碰红线）。

## §作用域分层（防混染+防膨胀）

1. **票级会话（主）**：每工单一个会话容器（写/语法门/考红/回喂追加/精修全在同一 messages 历史内）。
2. **轮级红因摘要账（辅）**：工单关闭（终局/绿）时压出「红因摘要 ≤3 行」注入轮级账→下一工单开盒首条带上（跨票继承·防「同因各踩一遍」）——与 M6 同因熔断互补（熔断止损·摘要预防）。
3. **全量隔离**：工单间不共享全量会话（防错误模式跨票误导+膨胀）。

## §关闭时机（四条并集·关闭=归档）

1. 整单 verdict 出（PASS/FAIL·正常收车）
2. 票终局 park#2（该票会话先行关闭·压摘要入轮级账）
3. 预算触顶（--max-llm-calls/--hard-stop-min·会话随轮终止）
4. 同错误码连续 N 轮早停（如 TS23xx 连续 3 轮→收敛无望提前关——run14-16 实锚可省 30 万+ tokens）

关闭动作：会话 jsonl 归档 `evidence/sessions/<ticket>.jsonl`——M1 诊断员（班间维修环）据此获得全量病历（两机制咬合点）。

## §设计草案（施工要点·候对比件拍板）

1. `llm-session.ts` 扩展：会话容器（messages 历史数组+轮次元数据+压实标记）——既有 SessionDigest 摘要族保留（向后兼容）。
2. `build.ts` 自愈环：feedback 从「重组全新 user 消息」改为「**同会话追加** user（回喂盒内容不变·形态变）」——assistant 上轮输出自然在历史中（previous_attempt 盒可退役或留作跨票场景）。
3. `llm-file-writer.ts`：messages 组装改造（首条系统+历史追加）·语法门红回喂同追加形态。
4. 压实策略：会话超 6 轮触发早期轮摘要化（headTail 哲学同款）·预算闸兜底不变。
5. 缓存前提冒烟（施工前）：provider 前缀缓存启用验证（智谱 context caching·两次同前缀调用第二次 usage 含缓存读）——不命中则本票收益减半·如实回禀。
6. 可观测：账本事件加 session_id 字段（lf-session 一班一 Session 概念对齐）·归档件入 evidence。
