# 检索体系设计理念总纲 · 分层召唤×场景路由×可重建投影（本窗结算版）

> **一句话总纲**：数据形态决定路线，前提核验决定缓议优先级，tripwire 是议程提醒器而非门禁——本仓检索体系的每一条设计决策都必须能还原成可复算的判据，且**任何一件都保持再议态**。
> **立场**：理念分析件（沿《五业务场景编排总图》体例）·只总结已拍事实与已验证思想·新动作一律候对比件拍板。

## §0 适用范围

本总纲结算主窗检索体系线(2026-10-22~23 集中期+此前零散铺垫)的全部设计决策:94 库检索管线(分层召唤/多源融合/rerank)、嵌入与重排选型(Qwen3-Emb-0.6B+bge-reranker-v2-m3)、场景×检索档案表(R1-R5)、VCP 借鉴结算（五项能抄＋缓议清单）、写入侧模式(权威事实层+可重建投影)、岗卡耦合协议(memory_source 行升级)、测量制度(考卷冻结/双跑均值/tripwire)。

## §一 检索管线设计理念：四通道编排·门在融合前

**管线总形态**（W-055/W-057/W-058/W-059/W-060 逐级建成）：

```
T0 确定性键短路（--kind/--tag/--scope/--hybrid 先滤后取·不进融合）
   ↓ 未命中
结构通道（B-1 确定性引用图：拍板↔窗↔卡边·零 LLM 抽边＋PPR 排序——第三/四批）
   ↓ 不足
词面 BM25（jieba＋bm25s.Tokenized·W-060 修复中文生效）∥ 向量（Qwen3-Emb-0.6B·双段 engine/common）
   ↓ 并行出候选
RRF 融合（k=60·倒数排名·同文档名次累加·唯一条目）
   ↓
rerank 殿后（bge-reranker-v2-m3 fp16·0.031s/查询实测）
   ↓
弱命中标注（⑤·top-k 均分 z<2.3·输出端零排序影响）＋ kind 柔性加权（⑥·--kind-bonus 缺省关）
```

**三条铁律**（每条有官方或实测背书）：
1. **门设在融合之前，融合之后不设线**——ES 官方：RRF 融合分后不可 rescore，否则异常（调研档题 2/4）；
2. **RRF 不怕分数不可比**——各路只按名次折算 1/(k+rank)（k=60 论文经验值·Qdrant 用 2·本仓以 eval 对表裁决，禁拍脑袋调参）；
3. **缺省关＋对表达标后另拍缺省**——每一路/每一开关上线都是两段式：显式开关灰度→对表数字→业主拍缺省（--rerank/--hybrid/--kind-bonus 同款，W-057/W-058 先例）。

## §二 场景路由设计理念：窗型即场景

**场景不用推断——组织形式已经把场景结构化了**。派工链的窗型、桥接的来源、票的大业务列，本身就是场景声明。路由三层：

| 层 | 机制 | 成本 | 覆盖 |
|---|---|---|---|
| 一 | 调用方声明（窗型/大业务 routeOf·已代码化 pi_runner:104） | 零 | ~90% |
| 二 | T0 键模式修正（拍板号→账本·病名→答疑·代码标识符→维修） | 正则 | 剩余大半 |
| 三 | 显式 --scene= 参数 | 人工 | 跨场景查询 |

**场景×检索档案表（R1-R5·业主拍定口径：厂务新建①并入优化③·检索需求聚类与流程编排分类不必一一对应）**：

| 检索场景 | 主源/通道 | 备注 |
|---|---|---|
| R1 厂务·修复（病） | cbm 硬影响面＋94 病卡软提醒＋hit_log 词面＋弱命中 | 岗卡 09/13 已按此写卡（双源软硬分栏先例） |
| R2 厂务·优化/新建 | 深度文档＋B-1 引用图＋94 优化档案＋复盘史（⑩） | ①③合并·业主拍定 |
| R3 项目·新建 | 宿主仓 App 代码图谱＋交件包考题＋样品窗档案 | **两产线检索分叉点**：项目线查宿主仓 |
| R4 项目·修复/优化 | 宿主仓修复班次＋回归门＋红账本 | R4/R5 将来可并·候业主 |
| R5 状态/账本（T0） | 台账/窗队列/runs | 键短路·不融合 |

**设计理念**：软硬分栏——cbm 图谱答"一定影响什么"（编译器验证级），标签联想答"历史上连带过什么"（提醒级·只产候选不产结论）。两者互补不互替；VCP 把文档共现联想当主力，是因为它没有代码图谱。

## §四 写入侧设计理念：权威事实层＋可重建投影

**母题（VCP 写入域深读提炼·AFK 原生拥有且更深一层）**：SQLite/索引只是可重建的投影，权威事实层先提交——AFK 版：**md 文件＝权威事实源（git 审计·人可读·append-only），storage＝可重建投影（gitignore·删库重建＝标准恢复动作）**。2026-10-23 嵌入换血的"归档式移除＋全量重建"实践的就是这条模式。

配套三件：①configHash 闸（换模型/换参数→缓存自动失效·W-057）②hit_log 契约日志（写入使用记录·喂升降级清单·W-055）③归档式移除（删除必可回滚·hit_log 等非向量资产保全回迁）。

## §五 岗卡耦合协议：检索能力上线＝只改 memory_source 行

岗卡 09 先例（拍板#58/#59）：检索能力上线**不改卡文进 prompt 区**，只改 frontmatter `memory_source` 行＋检索预处理件——机检三件套（check-roster/check-card-lint/check-consumers）管对账。编制盘点（拍板#56）指认"⑨病卡/⑩复盘史/⑬⑮病根表/⑭盯班笔记——五岗等同一份底层资产"＝正在建的检索体系；**⑯跨班记忆立卡与本体系同批拍**。可加机检：有卡岗缺 memory_source=WARN（对账闸·候选）。

## §六 测量与 tripwire 制度

1. **考卷冻结**：evalset 20 题＋词面集 15 题两卷并存·旧卷零字节纪律（W-059 实证守住·指纹 7927b83d）；
2. **双跑均值判定**：跑间噪声 ±0.04-0.09 实测（W-057/W-058 同库同码重跑漂移）——达标判定禁单跑；
3. **tripwire 三线**：标签图边≥500 且度≥3→L5 重开评审；索引≥10 万块→tantivy 货架；≥50 万块＋多轮图传播→自研 Rust 才议；
4. **对照实验单变量**：A/B/C 轮每轮只动一头＋影子库灰度＋不达标记档不采纳（#111 对比件 §9）；
5. **申报制**：超字面花费/依赖/事故一律如实申报候追认（W-058 双 main 事故 460 调用＋W-059 tokenizer 重大发现两先例）。

## §八 与 VCP 的哲学分岔（收束）

VCP:单一联想引擎兼任检索增强+影响分析(因为它只有日记);重数学(场论 14K 行 Rust)+实时性+多写方活服务。AFK:**分层召唤+场景路由+软硬分栏**--键/结构/词面/向量各司其职,md 权威+投影可重建,批次制 verified 闸门,制度化的影响面与追认。**两家不是谁抄谁，是数据形态与组织形式各自长出的形态**；能抄的是数学思想（PPR/PCA/GS/RRF 全是论文级经典·重表达仅 500-600 行）与工程护栏思想；暂缓迁移的是依附于对方数据形态的机器本体——**保持再议态**。
