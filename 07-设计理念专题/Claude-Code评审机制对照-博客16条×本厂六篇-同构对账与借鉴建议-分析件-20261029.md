## 〇 · 一句话总判

博客 16 条做法，本厂已有同构物 **12 条**（其中 4 条几乎逐字——三问审核、投票筛真三标、失败变题库、风险分级），真差距 **4 条**，本厂独有超出一大截 **5 条**。这不是巧合：两边在解同一道题——「概率性 agent 大规模写码时，质量怎么守」。**独立收敛是最硬的设计正确性旁证**；分歧处恰好暴露场景差：Claude Code＝「人团队＋AI 助手」（人在环上·PR 审批制），本厂＝「无人值守工厂」（人在环外·上游拍板下游追认制）。

1. **版本三本账＋版本 pin**——博客对「引擎自身版本化」只字未提（manifest 纪律镜面反射·钉版闸缺版拒启·五栏 sha 对账）；本厂动作八已落地（`版本钉版.mjs`＋run-slice.ts:137-140）；

3. **出题权纪律更彻底**——博客 AI 审核自由发现问题；本厂站4/站5 都不得出考卷·用例出生地在站2 规格器（Gherkin 纯函数零 LLM 编译·判据纪律篇 §2.2-2.4 循环论证/缝盲区/两层闸变一层三论）——**评测腐败防御比博客多一层宪制**；
4. **预算三路＋熔断**（博客无 token 经济学·本厂窗预算刹车/班判定梯/审批熔断三层）；

## 三 · 场景差根源（为什么分歧是合理的）

| 维度 | Claude Code | 本厂 AFK |
|---|---|---|
| 人在哪 | 环上（PR 审批·1人/2人批·谁合并谁负责） | 环外（上游拍板＋下游追认·push 由人） |
| 时态 | 同步协作（PR 天级流转） | 异步无人值守（夜车·晨报·代拍候追认） |
| 兜底 | on-call 值班·flag 分钟级回滚 | 晨报＋病卡维修环＋rollback＋停更分诊 |
| 失败代价 | 单 PR 可 revert | 一窗烧穿整夜预算/全线停摆（故预算闸/单飞锁/钉版闸） |

结论：博客机制是本厂机制的「人在环上版」——同构的部分可直接互为旁证，差异的部分不能硬搬（例如 blog 的 2 人批在本厂无意义·夜间无人可批——转译为停车候拍＋晨报追认）。
