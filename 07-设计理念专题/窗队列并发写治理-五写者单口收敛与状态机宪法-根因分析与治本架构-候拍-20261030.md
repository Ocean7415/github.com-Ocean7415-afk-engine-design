## §二 · 根因模型（一句话：共享可变状态，无事务）

窗队列 = **共享可变状态文件**，但它缺了并发系统_three_样东西：

| 根因洞 | 缺什么 | 今天对应 |
|---|---|---|
| 洞① 写仲裁 | 多写者无锁无串行化——行级修复 vs 全量回写互相覆盖 | 症状 5·1 |
| 洞② 身份租约 | 快照=出生证明（静态）非生命体征（动态）——旧残留不自知 | 症状 4·3 |
| 洞③ 规则强制 | 八态词面/转换权/写行纪律全是**文档纪律**——违反只有事后闸拦（拒投影/WARN），拦完还得人修 | 症状 2·7 |
| 洞④ 动作幂等 | 领单不查在飞窗——同票可重复拉 | 症状 3 |
| 洞⑤ 生命周期闭合 | 🔁维修中态无归属无超时——进入后无人负责 | 症状 6 |

三层归并：洞①=**并发层**（写竞争）；洞②=**身份层**（谁活着）；洞③④⑤=**规则层**（谁允许做什么、做完了没有）。

### 第二批 · 治本票：写口唯一化（根因手术·推荐终态）

**所有对窗队列的写，收编进一个 CLI**（提案名 `91-脚本/queue-write.mjs`）：

```

```

内部四道（串行·任一不过即拒写）：

1. **词面校验**：status ∈ WINDOW_STATES（window-card.ts:41 单源消费·零重复定义）；
2. **转换权宪法**：actor × 转换对查表（下表）——非法转换拒写并指路；
3. **乐观锁**：读时记 mtime+行版本，写时复核——不符即重读重试（行级原子·治洞①的全量回写覆盖）；

## §四 · 过渡期操作手册（写口落地前的标准动作·治本生效即废）

1. 卡面 vs 队列不一致 → **队列 md 为唯一事实源**，卡面只等投影（事件道/手动 sync），永不反改队列；
2. 僵尸通报 → 三问再动手：快照 pid 是哪次拉的？行翻▶距今多久？会话档还在写吗？；
3. 修行队列 → **一律行级精确替换**（禁全局字符串 replace——今日 W-181 误翻教训·已入行注记）；
4. 多窗竞态 → 不抢写不代裁，核账后合并认（W-182 先例：双窗产物趋同零 diff=判据收敛旁证）；
5. 🔁维修中卡点 → 先判红因：机检面红（如 W-088 挂载·修一次全厂生效）→ 修机检后重跑复考即绿；内容红 → 翻回待实施重领。
