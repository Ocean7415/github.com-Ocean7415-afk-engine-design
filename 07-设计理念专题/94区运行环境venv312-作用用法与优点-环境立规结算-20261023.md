# 94 区运行环境 `.venv312` · 作用、用法与优点（环境立规结算版）

> **一句话总纲**：`.venv312` 是 94 区（班外经验库 RAG）的**唯一合法跑测环境**——它把「检索栈齐全 + GPU 可用 + 版本钉死」三件事钉进一个隔离仓内目录，让每一次红绿灯都是真的。全局 python 没有检索栈，用它跑测=假红制造机；此教训两次实锤后由拍板#121 题5 立规封死（AGENTS.md L21）。
> **立场**：理念结算件（沿本目录总纲体例）·只结算已拍事实与已验证事实·不立新规不扩动作面。

| 项 | 实测值 | 锚 |
|---|---|---|
| 位置 | 仓根 `.venv312/`（AFK 无人值守引擎V1.0 内·gitignore 不入库） | `pyvenv.cfg` |

| GPU 栈 | torch **2.13.0+cu126**（`cuda=True` 实测）· sentence-transformers 3.4.1 · transformers 4.57.6 | `pip list` + 实测冒烟 |
| 配套模型 | qwen3-embedding-0.6b + bge-reranker-v2-m3（**仓外** models 目录·不进仓不进 git） | W-057 台账笔 |

## §一 在本项目中的作用（四个角色）

**角色一：检索栈的唯一供给者。** 94 区检索管线（`query_engine.py` 812 行·双段配额+RRF 融合+rerank 殿后+场景路由）依赖 bm25s/jieba/llama-index 系——这套栈只存在于 `.venv312`。W-058 施工时 venv 内尚缺 jieba 与 BM25 扩展包，按拍板#113 装包补齐（连带 bm25s/pystemmer·超字面一枚候追认如实申报）——venv 是依赖变化的登记载体，装了什么、为什么装，台账可溯。

**角色二：GPU 算力的落座处。** rerank（bge-reranker-v2-m3·fp16·cuda）与全量重嵌（Qwen3-Emb-0.6B·280.3s/1018 nodes/峰值显存 14.3GB，W-057 实测）全靠 torch cu126。没有这个环境，94 区的「精排殿后」与「缺省常开 0.713 配置」都只是纸面设计。

**角色三：假红防线（立规的直接动因）。** 本仓判卷纪律=红绿权 100% 归 exit code——**环境缺包造成的 ModuleNotFoundError 和真实代码缺陷在 exit code 上长得一模一样**，这就是假红。两次实锤：W-066 笔②（全局 py3.14 首跑 test_hybrid_rrf/test_bm25_wordface 两件 ModuleNotFoundError 假红→切 venv312 后 7 件 42 案全绿）；W-058 装包笔（venv 缺 jieba 假红风险，装包后闭环）。判卷体系最怕「红不真红、绿不真绿」，环境统一是红绿可信的地基。

**角色四：数字可复算的锚。** 对表台数字（六格 eval·0.713 缺省配置）、全量回归（8 件 61 案，W-078 收口数）、建索引缓存指纹——全部出自同一解释器。跨窗（主窗/施工窗/派工器拉起的窗）谁跑都是同一个 Python，数字才有跨窗可比性。

## §二 怎么用（两种姿势+一张命令清单）

**姿势 A·内联激活**（交互多命令时用）：

```bash
source "D:/AI/Project/pi agent/AFK无人值守引擎V1.0/.venv312/Scripts/activate"
python 94-班外经验库RAG/query_engine.py --retrieve "你的问题"
```

**姿势 B·绝对路径直调**（推荐·单命令免激活·代理跑测首选）：

```bash
.venv312/Scripts/python.exe 94-班外经验库RAG/build_index.py
```

**典型命令清单**（全部已在台账实跑过）：

| 做什么 | 命令（在仓根执行） |
|---|---|
| 全量回归（8 件 61 案） | `.venv312/Scripts/python.exe 94-班外经验库RAG/tests/test_<名>.py`（逐件直跑·exit 0=绿） |
| 建索引（增量·缺省） | `.venv312/Scripts/python.exe 94-班外经验库RAG/build_index.py` |
| 检索冒烟（缺省 hybrid+rerank 常开） | `.venv312/Scripts/python.exe 94-班外经验库RAG/query_engine.py --retrieve "问题"` |
| eval 对表（六格） | `.venv312/Scripts/python.exe 94-班外经验库RAG/eval/run_eval_grid.py` |
| 装新依赖 | `.venv312/Scripts/python.exe -m pip install <包>` ——**装包=依赖面变化，须台账如实申报候追认**（W-058 先例） |

**三条纪律**（拍板#121 题5 · AGENTS.md L21 在案）：
1. **94 区跑测/eval 一律 `.venv312`**——全局 py 无 bm25s/jieba，跑了就是假红，红绿证据直接作废重跑；
2. **代理会话注意**：每条 bash 命令是独立 shell，激活不跨命令保持——要么命令内联激活，要么全程绝对路径；
3. **模型不进仓**：两枚模型住仓外 models 目录，venv 只管代码依赖——仓可随时删库重建（索引=可重建投影母题），模型与缓存分键（configHash 闸）各守其位。

## §三 优点（对照全局 python 逐条）

| # | 优点 | 对照面 |
|---|---|---|
| 1 | **隔离干净**：`include-system-site-packages=false`，仓内包与全局包互不渗漏——不会出现「全局升了某个包把仓内跑测带崩」的暗雷 | 全局 3.14 装包=污染所有项目 |
| 2 | **版本钉死**：3.12.13 由 uv 托管，跨窗跨日同一解释器——今天 61 案绿，下周重跑还绿，数字可复算 | 全局 python 会随系统升级漂移（3.14 就是漂移产物） |
| 3 | **检索栈全**：bm25s+jieba+llama-index 系一键齐——94 区全部产线码与测试开箱即跑 | 全局缺 bm25s（实测 ModuleNotFoundError）·装全局=假红换真污染 |
| 4 | **GPU 就绪**：torch cu126 实测 `cuda=True`——rerank 0.031s/查询、全量重嵌 280s 可承受 | 无 GPU 栈则 rerank/重嵌不可行，0.713 缺省配置无从谈起 |
| 5 | **假红免疫**：环境错≠代码错在 exit code 上不可辨——统一环境后，红=代码真有病，绿=真没病 | W-066 笔②：全局跑测两件假红，浪费一轮排查 |
| 6 | **仓库轻**：venv 与模型均在 gitignore 面——仓体不带数百 MB 二进制，删库重建是标准恢复动作 | 依赖入 git=仓库膨胀+二进制冲突 |

**母题一句话**：`.venv312` 是「权威事实层+可重建投影」写入侧母题在**环境域**的同构物——代码+依赖+数字产出（storage/hit_log/eval results）都是可重建投影，唯有人可读的规约（AGENTS L21 一行）与账本（台账/拍板表）是权威层；环境塌了，`python -m venv` 重装+跑回归即恢复，规约不用改一个字。
