〇、一句话总纲

同一台引擎，四层流程各管一段，层间只有两个交接面。用例层管「考题从哪来、谁能动」（增删改查·姊妹件矩阵）；票内层管「一票怎么修」（自愈 ⟲≤3）；班内层管「一夜怎么走」（波→段→收车）；班外层管「修不好怎么办」（维修环+自举飞轮）。层间交接面只有两个：班收车（账本+晨报+病卡交出去）与考题追加（协议唯一路·票级 cap3/切片 cap6）。维修环/引擎维修工程师在班外层——它面前是收了车的整班，不是班内的票。

读图纪律（CONTEXT.md 三词）：每层标注谁在场——机械设备（确定性代码）/ Agent员工（LLM 调用面）/ 自然人审核（只有业主能做）。层越往外，机械设备占比越高、Agent员工占比越低。但越往外层，对在场 Agent员工的要求越高——需要更贵的 LLM 模型（E1 strong 档），以及 +RAG 系统垫底（整班证据检索注入）；在场的少而精，是设计取向：班外错不起。（实然注记：E1 strong 档旋钮已在位（model-tier.ts·拍板#8），班外岗现走缺省档；RAG 检索面未建——设计取向与现状如实分列。）

一、层级总览（一圈套一圈）

班外层（收车之后·维修环+自举飞轮·机械设备为主+自然人深读/拍板） │ 交接面①：班收车 → 账本 events.jsonl + 晨报七栏 + 病卡 │ │ 班内层（一夜·段级流水·机械设备调度+Agent员工施工） │ │ 段0 预检 → 段1 拆单 → 段2 车道(波) → 段2.5 探针门 → 段2.7 功能门 → 段2.8 硬化道 → 段3 回归门 → R13 判定梯 → 收车 │ │ 交接面②：考题追加协议 → 判卷面/切片面（唯一加题路） │ │ │ │ 票内层（一票·自愈环·Agent员工施工+机械设备守门） │ │ │ 预投 → 锁定 → 生成 → 语法门 → 验收(judge-guard 闸) → 自愈⟲≤3 → L3 偏移弹 → 降级链 │ │ │ │ │ │ 用例层（考题的生灭·增删改查·见姊妹件矩阵） │ │ │ │ L1 正本(业主/站2) · L2 判卷面(只增不改不删) · L3 切片面(只增+白名单改) · L4 词汇层(机械设备全权)

每层的重试预算：票内 ⟲≤3（判据追加 cap3/票）· 班内段级各 ⟲1 + 夜末补考 1（park≤2）· 班外自动修 ≤1 轮（`--loop-budget` 缺省 0=关·同病≥2 转人工）。

三、票内层 · 一票怎么修（自愈环 ⟲≤3）

预投(拍板#80·机械设备·考题先在盘上) → 锁定(judge-guard·#82/83·篡改=红旗终局) → 生成(Agent员工·deliver=[target]·W7 修法A 考题只读) → 语法门(py/tsc·红=当生成失败) → E10 零提交闸(交付域零变化=红·零LLM) → 验收命令(红绿唯一权威 #28②) → 绿 → 收工（defer→硬化道） → 红 → 自愈 ⟲≤3(喂报错重写·机械设备编排+Agent员工重写) ├─ ⟲≥2 → L3 偏移弹(采样 drifted?·early_stop 唯一自动项) ├─ 建议加题 → 判据追加协议(#11·QA 起草→只加严机检→sha256 重锚·cap3/票·唯一加题路) └─ ⟲尽 → 预授权降级链(素材直搬·auto 模式) → 仍红 → park#1（换下一票）

谁在场：Agent员工（生成/重写）+ 机械设备（门/闸/锁定/编排）。自然人不出场（自决·⟲ 预算内）。

四、班内层 · 一夜怎么走（段级流水·各段 ⟲1）

段0 预检(六硬项·零LLM) → 段1 站3 拆单(三关+判卷素材冻结入账) → 段2 车道(波屏障/就绪制·逐票=票内层·dep-guard 连坐·park≤2) → 段2.5 探针门(第二层探针·⟲1·补票环/锚点起草道·红只入账) → 段2.7 功能门(切片①·⟲1 自愈/考题病修复道/切片追加·锚点分诊 hold·功能红不烧硬化) → 段2.8 硬化道(CRAP∧变异·三钥匙·仅功能绿票) → 段3 回归门(切片②·主判·翻案⟲1) → R13 判定梯(NA≥20%∨交互片未执行→FAIL) → 收车(夜末全量灯 W8·晨报七栏·病卡/诊断/方案件)

谁在场：机械设备主导（调度/门/梯/判定）+ Agent员工（施工/审查/自愈）+ 自然人不出场（夜内零停·自决点全入账）。班不会因为卡住自动重跑很多轮——票卡住=park 停车，班到点=收车；整班重跑只在班外（§五）。

W13件①（拍板#22·sandboxStaticPatch）：段2.8 的 CRAP∧变异两闸（静态分析闸）不进 docker 容器——docker 档宿主直跑（bind mount 直写文件在场）/ worktree 档仍走影子树（未 syncOut）/ none 档透传零变化；build-lane 两闸注入改道·300 行顶格保持。分类案三档单测+834/834 全绿+docker 档真跑 runs/w13-docker-v1=8/8 整单 PASS（docker 档转正）。

W14 M1（拍板#25·2026-10-13 上线·业主站6 追认）：收车半段六件编排独立拉起——班外优化 agent postshift（病卡→诊断→方案件→信号→复盘→深化·每件失败不挡后续）；双模式=手动复盘令+--watch 监听 queue_gate_failed/passed（state 记 offset 防重复）；深化缺席告警置顶进 postshift-summary.md；规格卡红线=零代码写入·零重跑·零判卷触碰·预算独立分账（诊断 ≤5·深化 12）。落位实况（v1.7 定案）：pipeline-lab 收车链件权威位=本仓（引擎仓 Oct 11~12 新版全数在场）；postshift.mjs 2026-10-13 落位入仓（与深读件哈希同源 6f878110）；外层沙盘仓同名件=Oct 8~10 旧版副本待清（防双权威——沙盘版无拍板#74 双协议/#22 cachedTokens 新语义）。

五、班外层 · 修不好怎么办（维修环+自举飞轮·自动修 ≤1 轮）

收车四连(nightrun-wrap·病卡 report-issues→诊断 diagnose→方案件 propose-fix→晨报) → FAIL 班 → 维修环 fail-loop(`--loop-budget` 缺省 0=关·发车令三要素之一) → 逐班：诊断 force → 编译四闸 → 分流 classify ├─ L1 机械类 → repair-auto(预授权·≤30 行/≤5 文件·晨报事后追认) ├─ L2 回归子类(scope⊆上窗施工文件) → repair-auto·regression(引擎测试闸 tsc+vitest·晨报待追认) ├─ L2 新语义 → stop-approval(业主勾选闸·不绕行) └─ 无 lane → rerun-only(重烧红票·绿缓存直通) → 重跑(新窗续号·指纹缓存绿直通) → 绿 → 病卡已修✅台账 append → 仍红(同病 FAIL≥2 轮) → 停车转人工+深读清单(#84④·机械修复不盲烧) → pi 复盘窗深读(自然人) → 结论含「规则缺口: 是/否」 ├─ 是 → 齿A 立票接线(rule-gap-ticket·A-LANE 草稿票落 pending·无拍板号不入列队) → 拍板后治产床（#72 双修律） └─ 否 → 修实例结案

谁在场：机械设备为主（fail-loop 编排/A 域车道·deepread 零 LLM·引擎测试闸）+ 自然人（深读归因/L2 勾选/拍板）。A 域（引擎自身病）只能自然发生——不为考试往引擎放毒（R2-13 §5 诚实边界）。
