§一 · 自举流程定稿（业主确认·2026-10-28）

第二层用 L1.n 实施新功能/维修 → 产出 L1.n+1 候选 → 留出考题核账＋业主终认 → 上线 → 骨架若有升级，第二层择机拍板跟进（不强绑）。

口径注：本件全部「L1.n/L1.n+1/L2.m/S1.x」记法服从此句——实例版本独立演进，只有骨架基线是同步面；「强绑同号」被业主明确排除（上轮尺病论证在案：考官版本须独立于被考版本·教义七）。

§四 · 优缺点（代码实态修正版）

#优/险实态依据处置
1优·成绩可归因manifest versions 先例＋版本档案四轨——只差 harness 侧 pin步①②
2优·生产/被改物理分离spawn 子进程边界＋sandbox worktree 现成沿用·零新造
3优·考官独立性有先例复考闸 exit code 唯一判据＋考题库业主拍板制（#207）步③留出加列
4险·尺病代际传染3 清单无留出概念——同一套题既日常复考又终核步③＋业主终认道版本外
5险·双版本维护税单包结构无多版本机制在役只留两代（V_n 生产/V_n+1 发育）·缺陷默认 cherry-pick 两版
6险·顺序陷阱「完全优化好再做版本管理」=移动靶无锚倒序：版本管理先行——pin 即度量基础设施
