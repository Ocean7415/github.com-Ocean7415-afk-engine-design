三层验证门 · 真班贵慢粗账目对比 引擎 vs 传统 Claude Code / pi 直接编程的抗幻觉优势

理念分析件 · 2026-10-18 · v2 增补 §三 站点4（开发部抗幻觉机械逐件对照）· 07-设计理念专题 · 账目源=执行台账/交接件实测（37 万 token/27 调用/145 分钟/Σ228.5 万均为真班实锚）· 业主问「重放为什么贵慢粗·能否对比」＋「这也是引擎相对传统直接编程的优势」

§0 一句话总纲

传统 Claude Code / pi 直接做程序＝大模型写＋大模型自述＋人肉兜底——判卷权在模型手里，装绿/幻觉靠人抓；AFK 引擎＝大模型写＋机械判卷＋人只看判定梯——判卷权从模型手里拿走，变成 exit code/考题 hash/判定梯这些可复算的法律。差异不在"谁家模型写码更强"（都是大模型写），在"信不信它说自己写对了"。本件用真账说明：为什么这条路上"验证"贵慢粗到必须分三层，以及为什么这个分层本身就是引擎的护城河。

独有价值静态/单元边界测"真生成"：胶囊回放旧响应，永远验证不了"改 prompt/判定策略对真实生成质量的影响"；也唯有它能暴露"真实 LLM 输出喂进下一站会不会炸"（API 漂移/格式方差/分段边界——痛点01 族）测"管道逻辑"（录制响应喂全链·各站衔接断言）

结论：贵＝真生成必须重跑；慢＝串行+真生成耗时；粗＝全包粒度＋生成方差污染归因。三者同源——LLM 在回路里。所以重放不能砍（真生成质量唯有它能验），也不能常跑（贵慢）——中间必须补一层确定性门。

§四 为什么这套三层门＋站4 是引擎相对「传统直接编程」的优势

4.1 结构对比：判卷权在谁手里

传统 Claude Code / pi 直接做程序：大模型写码→大模型自述"完成了"→人肉 review 兜底（LLM 审 LLM 或人看·不系统·不可复算）
AFK 引擎：大模型写码→票面验收 exit code（零 LLM）→对题闸（状态机无 red→reviewing 边·只能扣绿永不放红）→站5 双证＋判定梯（PASS/PASS*/FAIL）→人只看判定梯（可复算）

公平说明：Claude Code / pi 也能跑测试——差异不是"有测试 vs 没测试"，是"测试是不是法律"：①考题与实现分离且开工前冻结（judge-guard sha256 锁·篡改=终局）②判卷权形式化（reviewer 状态机无 red 入边·判卷零 LLM）③失败处置有上限有动作（自愈⟲≤3/宁停/停车场·红账本 2 轮复发自动升级）④全链 receipts（events.jsonl 115 型白名单·跳过也记账·run_interrupted 留痕）⑤NA≠PASS（没测到≠通过）。这五条在直接编程里靠"人自觉"，在引擎里是架构硬保证——不是管理制度，是调用链和状态机里写死的边。

§五 厂务线如何继承这套优势（ts 码件的三层门＋站4）

引擎仓改引擎（厂务修复/优化）时，判卷面天然已存在：四关＋1086 条测试＋真班重放——全是零 LLM 机械件。所以厂务线抄这套作业的成本最低，只缺中间层（§二胶囊）和形式化梯（R-F）：

厂务判定梯（拟·R-F）机械判据
PASS四关全绿 ∧ 胶囊全绿 ∧ 重放 EXIT=0 ∧ 快照零幽灵 ∧ 事件白名单零新增
PASS*（带星）四关＋胶囊全绿 ∧ 重放候跑（挂晨报·下一班补）
FAIL任一红 → 按任务书分诊（机械缺陷🔁修／语义回拍板／判据问题出证）

这就是 ts 码件窗敢入 L2 白名单的钥匙：现在不敢让子窗自动改 ts，是因"四关绿"覆盖有盲区；有了胶囊门（快而确定）＋重放门（慢而全真）两级机械判卷，白名单才有判卷底气——子窗改码→四关＋胶囊自动跑→绿才收口→重放夜里链式→晨报追认。第一步顺风件：下次真班 CASSETTE=record 录一批（fixtures/cassettes 从 0 到 1——深读窗交接 §四4 已挂）。

§六 边界（诚实项）

  • 机械判卷治"装绿/漂移/越界/静默"，治不了"测试本身写错了"——所以任务书判据冻结＋业主批判据仍是闸门（出题权在人）；
  • 测试覆盖不到的行为盲区依旧盲（四关/胶囊是必要非充分）——真班重放与概率族观察价值不变；
  • 胶囊回放旧响应：换模型/改 prompt 后须重录；重放的非确定性使"单次红"须按概率族口径处置（重放可消化·不一次定罪）；
  • 传统方式若配齐"冻结考题＋机械判定梯"也能近似——本件主张的差异是系统化程度（五条架构硬保证 vs 人自觉），不是能力有无。
