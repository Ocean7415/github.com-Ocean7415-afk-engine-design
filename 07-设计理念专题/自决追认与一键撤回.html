四、理念②：撤销令随件落地（undo at write-time）

在做好的同时就写好怎么拆、怎么返回——撤销令不由人事后重建，由机械设备在动文件之前从 before-state 派生。

4.2 铁律：撤销令由机械设备派生，不由 LLM 起草

安全钉子：Agent员工既能改码又能写撤销令，追认环就被架空。故撤销令字段 {op, path, prior_sha, 关联事件 seq} 全部机械生成（改动前状态在案：judge_assets_frozen/judge_freeze_locked/影子树基线锚）；LLM 全程只起草正向产物。
v2.0 as-built：shared/undo-plan.ts 三形态实装（delete_file·expectSha 现场校验／restore_file·先存后用备份 .undo/／state_reburn·状态回退标记——物理返工走下轮补票/resume 如实不装）；confirm.ts --rollback 实装（与 --reject 并用·逐条校验→逆操作→rollback_applied 入账·漂移拒执行如实）；撤销令机械派生铁律有守卫测试锁死（LLM 草稿携 undo 字段=机器从写入内容重算覆盖）。v1 边界（如实）：补票/降级等深修票的物理撤销走状态标记+既有轮闸/量闸管辖；锚点起草令的 ticketId 回填留后续窗。

4.3 撤回闭环流程

自决动作执行时（机械设备）：动文件前 → 派生撤销令 → 入账（伴随事件或 *_undo 事件型·先登记白名单再用）
　↓ 站6 晨报：追认栏每条自决带「撤销计划」人读行（RecoveryMessage 式）
　↓ 业主推翻（confirm --reject 已入账）→ --rollback 执行器：
　　读账本撤销令 → 现场校验（当前 sha == 令内 prior_sha 才动手·防漂移）→ 执行逆操作
　　→ 账本追加 *_revoked → 该票判据指纹失效 → 下轮按 miss 如实重烧
已出报告不改写（账本 append-only）——撤销不洗绿：与拍板#82/#83 加严失效同一把锁，方向反过来

五、理念③：工作区 git 化三护栏（一键撤回的载体）挂账·Q4b-B 独立后置窗

护栏为什么做法
① 分区隔离git revert 若连账本/晨报一起回滚＝抹痕，违反 append-only 留痕纪律git 只管码区；ledger/、report/、.judge-freeze.json、changes/ 排除在 revert 面外。撤回＝git revert（码区）＋账本追加撤销事件（痕区），两笔并行缺一不可
② commit 粒度＝自决粒度「撤回相关变动」要按票/按决策撤，不能整夜一坨每笔自决一个 commit：机读约定 auto:<kind>:<ticketId>:<seq>；变动清单投影不用自建（git log 即是）；归档打 tag、不 squash（squash 毁粒度）
③ 撤回不洗绿git 只回滚文件态，判卷语义必须原样撤销后快照再变→旧 verdict 失效按 miss 重烧；已出报告不改写；push 仍业主亲自（仓红线 4 不动·ws 内 git 纯本地）

成本面：git 二进制进 preflight 探针（runtime-probe.ts 模式加一查）；每夜车 ws 在 scaffold（workspace_scaffolded 事件已有）时 git init+基线 commit；Windows 挂载毛边 sandcastle 已踩过（createWorktree-windowsMounts.test.ts）。依赖关系：undo 令（理念②）不依赖 git 可先行——令的语义在文件系统面钉死，git 化后令的载体自动变成 commit，执行器退化为 git revert 编排。
