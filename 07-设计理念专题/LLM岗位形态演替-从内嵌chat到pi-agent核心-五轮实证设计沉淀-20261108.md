# LLM 岗位的形态演替 · 从内嵌 chat 到 pi agent 核心（run13-17 五轮实证 · 设计理念讨论沉淀 v1.0 · 2026-11-08）

> **TL;DR**：引擎的 LLM 岗位存在两条形态路线——**内嵌 chat 直调**（llm.ts·单消息·引擎编排回喂）与 **pi agent 核心**（完整 pi 会话·工具循环·天然会话与缓存）。App 优化混合检索任务五轮同尺实证钉死了分工：**pi agent 核心承载的 L2 形态 332,296 tokens 一轮交付+维修段全绿；内嵌 chat 承载的 L1 形态五轮 1,193,529 tokens 四种形态逐轮跳变未收敛**。归因主因=迭代闭环结构差异（连续会话精修 vs 无状态重抽），而非模型差异（同为 glm-5.3 系）。治法三层已落地或候选：内嵌路线止损（红因提示盒×3·#498/#499/#500）、会话持久化 MVP（#501·追加形态+归档咬合）、pi agent 核心化（站 4 转正候选·判卷闸永驻机械）。**混合终态**：重迭代岗 pi 化、判卷闸永驻机械、单发起草岗保持内嵌。
>
> **立场**：设计理念讨论沉淀底稿（md 形态·本区权威形态=HTML 成品件·拍板#35——HTML 成品化候拍）；只沉淀已实证事实与已落地治法·候选项如实标注。

## §二 归因五层（为什么 781k→1.19M 未收敛而 332k 全绿）

| 层 | 归因 | 实锚 |
|---|---|---|
| ① **迭代闭环结构（主因）** | L2=同一 pi 会话内多循环自验精修（上下文连续）；L1=无状态单次重写（每次调用全新 prompt·每轮从零换实现策略·140→79→170→160 行四套架构） | 四轮四形态逐轮跳变 |
| ② 缓存经济 | L2 前缀稳定→cacheRead 7.69M（重复上下文≈1/10 价）；L1 回喂盒内容变化→指纹命中 0%（每次全价）·单调用密度 13.2k vs 4.5k（差 3 倍） | 晨报 §三 |
| ③ 自验深度 | L2 自验期暴露并修掉并发争抢（51.3s→10.5s·单飞锁+线程帽）——只有活着跑进全量测试才现形；L1 四轮死在语法门/挂死（更早关卡）·从未触达深层 | L2-done §三.7 |
| ④ 域难度 | 同步桥+本地 ONNX 推理+worker 通信=高难新域——对两者同等难，消化方式不同（L2 迭代密度消化·L1 期望一次到位不现实） | 五轮五病 |
| ⑤ L1 的钱买了什么 | 形态库 +6 条实锚（第 13/14 形态+四亚型+稳定触发法）+机制全线验证（语法门/park-补考-终局/M6 熔断首战/连坐保护零破坏/判卷零触碰）——**实验资产非交付物** | 判卷存证族 |

## §三 概念澄清四则（讨论中的关键概念）

### 3.1 「盒」是什么

盒（box）=**给 LLM 单次调用的上下文包裹物**——「输出协议的请求面（ADR-0002·指令/数据分离）：任务槽/约束槽/契约面/输出协议」（llm-box.ts:4）·「传给 LLM 的一切皆为 JSON 数据」（:17）。盒族四类：**变量盒**（正向上下文）/续写盒（已收全文·拍板#57）/单段重发盒（缺段+锚点·拍板#63）/**回喂盒**（红因回喂·六路：案三元组+红因提示盒+failOut 头尾+previous_attempt 环切+implCtx 断言键定位片段+判卷锁定声明）。「TS2339 盒/挂死盒」=回喂盒里按红因类型追加的**专属药方条**。

### 3.2 应用层 reducer ≠ provider 层缓存命中（两层区分）

langchain 的消息归约器（add_messages 类）/trim_messages 管的是「**应用层怎么组织 messages**」；缓存命中发生在「**provider 层前缀字节匹配**」。两者条件：①消息序列前缀字节逐字节稳定（追加式）②provider 缓存开启（anthropic 形态需 content block `cache_control` 标记·智谱 context caching）。引擎「指纹命中 0%」根因=每调用单条内容不同的 user 消息（无共同前缀）——**不是缺 reducer**。#501 的 buildMessages（追加形态·十几行）与 langchain reducer 语义同构——引框架只换 API 糖·违背引擎零依赖哲学·不取。待验真点：兼容端点对 cache_control 的支持（冒烟项）。

### 3.3 pi agent 的循环范式

pi = **工具调用循环（tool-use loop）**——广义 ReAct 家族，现代实现走 native tool-use API（结构化 tool_use 块·非文本化 Thought/Action 协议）：系统提示+工具定义→LLM 输出（文本和/或 tool_use）→harness 执行工具→tool_result 回喂→循环至无工具调用。「自然闭环」=写→跑测试→读输出→改发生在 agent 内部（工具结果零衰减直接进上下文）——对比内嵌车道「引擎编排器拼回喂盒（信息经 headTail 截断衰减）」。

### 3.4 pi agent 核心七件套

会话容器（jsonl 持久化）/系统提示层（AGENTS.md+skills）/**工具层**（fs/bash+MCP 扩展）/**循环器**（tool-use loop）/权限安全层（信任模式+红线守门员+领地闸）/provider 层（多源+双相超时）/**compaction**（上下文超限自动摘要）。内嵌 chat 的对应物：①=TicketSession（#501 MVP）②=变量盒 system 段③=**无**④=**无**（引擎编排器替代）⑤=变量盒指令/数据分离+预算原子（不同层）⑥=llm.ts（不弱）⑦=headTail 环切（粗版）。

## §四 七维对比详解（内嵌 chat vs pi agent 核心）

| # | 维度 | 内嵌 chat（实锚） | pi agent 核心 | 差距本质 |
|---|---|---|---|---|
| 1 | 会话记忆 | 每调用单条 user；#501 后 TicketSession 手拼 MVP | jsonl 持久化天然 | 手拼 vs 原生 |
| 2 | 前缀缓存 | 指纹 0%（单消息+cache_control 未打） | 追加前缀稳定→7.69M 命中 | 追加形态=缓存命中的本质条件 |
| 3 | 上下文裁剪 | headTail 环切（400 字/轮） | compaction 自动语义摘要 | 粗裁 vs 压缩 |
| 4 | 工具 | 无（吐文本·引擎代写盘） | 原生 fs/bash（自验-修内化） | **L2 一次收敛的直接原因** |
| 5 | 迭代闭环 | 外部闭环（编排器拼回喂·盒衰减） | 内部闭环（工具结果零衰减进上下文） | 盲改 vs 精修 |
| 6 | 控料/安全 | 变量盒指令/数据分离+预算原子 | 窗边界闸（白名单/领地/预算刹车+守门员） | 防护在不同层——**判卷闸族两态均机械（红线）** |
| 7 | 单次成本 | 轻（一条消息直调） | 重（agent 壳+工具定义） | **单发起草岗内嵌划算**（混合终态理由） |

## §八 选型律与边界

1. **一次性任务→L2（pi agent 核心）**：332k 全绿 vs 1.19M 五轮未收敛——不对称性实证。
2. **高频同构+愿投适配→L1（真引擎）**：形态库积累是收敛路径（每轮真弹入库→闸/盒扩面）·骨架预投可加速。
3. **判卷永不 LLM 化**：exit code 唯一红绿权——任何形态变革的红线。
4. **止损纪律**：预算三路+语法门快速失败+M6 熔断——试错从「失控燃烧」（D 形态 12 轮 210 万）变成「可控采样」（四轮 78 万买 6 形态·单位形态成本降 3 倍）。
5. **边界**：本件为讨论沉淀底稿（md）——HTML 成品化候拍；治理三票与 #501 的 B 级细节代拍候追认；L1 后续（甲收兵/丙骨架预投）候业主终裁。
