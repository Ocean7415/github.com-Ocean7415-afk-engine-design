# AFK Engine · AI 无人值守自动研发引擎 — 设计文集

> 这是一套「让 AI 无人值守地完成软件研发交付」的多智能体引擎的**设计文档集**：
> 7 张状态机卡 + 13 册机制目录，覆盖从任务进料、施工、验收判定、维修自愈到预算治理的全链路设计。
> 本文集为设计文档，不含源码；全部机制均在生产化运行的真实引擎中落地并留有实测记录。

## 这个引擎解决什么问题

现成的多智能体框架（LangGraph 等）只接管「编排」这一层。要真正做到**无人值守**，还需要回答：

- 施工质量谁来判？（验收判定权必须与施工权分离——机械先判，Agent 不得自判红绿）
- 失败了怎么办？（失败分诊 → 续写修复 → 模型升档的受限自愈环，只治认得的病）
- 成本怎么管？（单票三路预算护栏：调用次数 / 金额 / 时钟，软阈值降档、硬阈值熔断）
- 出事怎么查？（事件溯源账本 append-only，117 型事件白名单，全链留痕可回放审计）
- 多写者并发怎么不踩？（唯一写口 + 行集指纹哨兵对账 + 写前滚动备份）

实测：单次夜车 5 小时跨班五版连续派班零人工介入；红票即刻拦停不烧后续预算；人从全程盯守降至手机拍板。

## 核心设计思想（三词总纲）

| 角色 | 含义 | 约束 |
|---|---|---|
| **机械设备** | 确定性代码 | 不叫 LLM、算得准、可重放 |
| **Agent员工** | LLM 调用面 | 起草/施工/审查/自愈，产出有概率性 |
| **业主（Owner）** | 人类决策者 | 只拍不可逆动作与终认 |

一句话：**概率性产出必须被确定性机制判卷，不可判卷的升级给人。**

## 术语表

| 术语 | 含义 |
|---|---|
| 业主 | 系统中的人类决策者（Owner）——只拍不可逆动作 |
| 票 / 窗票 | 一个可独立施工与验收的工作包及其生命周期载体 |
| 红绿 | 验收失败 / 通过——判定权在机械闸，不在 LLM 自评 |
| 夜车 | 夜间无人值守的连续派工批次 |
| 波 | 夜车内的一批次（波屏障：本波终态才放下一波） |
| 帽 | 预算上限（token / 金额 / 时钟三路） |
| 宁停 | 证据不齐时不动作、记因候查——宁停不装绿 |
| 拍板#N / W-N | 内部工程仓的决策台账与工单编号（公开卷中为死链，属预期） |
